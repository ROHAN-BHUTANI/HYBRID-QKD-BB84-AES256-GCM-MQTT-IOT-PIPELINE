## 5. Random Seed & Determinism Architecture

To guarantee exact auditability while respecting cryptographic entropy requirements, pseudorandom generation is partitioned:
1. **Cryptographic Key Material & Nonces:** Generated via OS CSPRNG (`os.urandom(32)` for test keys, `os.urandom(12)` for 96-bit AES-GCM nonces).
2. **Qiskit Aer Simulator Seed:** Driven by Python `random` / OS entropy; circuit shots default to 1 (single-photon simulation).
3. **Cascade Multi-Pass Permutations:** Pass 0 operates on sequential blocks; passes 1–3 use deterministic PRNG shuffle seeded with `random.Random(42 + pass_idx)`. This ensures reproducible error decoupling across independent executions.
4. **Toeplitz Universal Hashing:** Deterministic 2-universal matrix expansion uses public seed bytes `b"QKD-BB84-TOEPLITZ-SALT-2026"` expanded via SHA-256 in counter mode over $\text{GF}(2)$.

## 7. Explicit Research Boundaries & Limitations Statement

Every researcher replicating or evaluating this testbed must observe the following scientific boundaries:
1. **Simulation Model:** Quantum circuits are simulated using Qiskit Aer statevectors on classical x86_64 hardware, not physical optical fiber or photonic emitters.
2. **Classical Authentication:** The classical channel during basis announcement and Cascade parity exchange is assumed to be authenticated (e.g., pre-shared Wegman-Carter). Classical MAC key consumption is not modeled in the software post-processing loop.
3. **Engineering LHL Approximation vs. Composable Security:** The implemented key extraction length $\ell \le \lfloor m(1 - h_2(\text{QBER})) - \text{leak}_{\text{EC}} - 64 \rfloor$ is an engineering approximation of the asymptotic Leftover Hash Lemma. Under an illustrative composable finite-key benchmark (Tomamichel et al. 2012) incorporating Serfling phase-error confidence bounds ($\delta_{\text{PE}} \approx 0.255$) and a 160-bit composable margin applied to an idealized conjugate-basis protocol, $N=1024$ and $N=1536$ yield 0 secret bits. Reaching $\ge 256$ secret bits under that hypothetical benchmark requires $N \ge 3072$ at $\text{QBER}=0$ ($\ell \approx 297$ bits) and $N \ge 8192$ under realistic noise ($\text{QBER} \approx 0.04$, yielding $\ell \approx 334$ bits after deducting $863.4$ bits of Cascade error-correction leakage). Because the actual software implementation samples from a mixed basis pool and measures bit error rate rather than conjugate phase error, the codebase is designated an *experimental privacy-amplification demonstration*, not a certified finite-key QKD deployment.
4. **Transport Layer Scope:** Live Eclipse Mosquitto was not executed on the test host. Measured E2E transit times reflect the in-memory Python `SimulatedBroker` queue fallback ($0.33$ ms dispatch latency, $380.6$ ms sequential pipeline execution). No claim of live-broker network round-trip validation is made.
5. **Post-Quantum Baseline Attribution:** The ML-KEM-512 handshake time ($2.15$ ms) in Table VII is an established literature reference from Shehzadi et al. (IEEE ISCAS 2025) on ARM Cortex-M4; it was not measured locally because `liboqs` was unavailable. It evaluates algorithmic KEM execution and is not directly comparable to Qiskit Aer quantum circuit simulation ($805.1$ ms).
6. **Eve Detection Statistics:** At small block sizes ($N=200$), parameter estimation exhibits an empirical False Acceptance Rate of $6.0\%$ at $p_{\text{eve}}=1.0$ and $42.0\%$ at $p_{\text{eve}}=0.5$ due to finite sampling variance ($n_{\text{sample}} \approx 25$ bits). The 100% empirical detection observed at $N \ge 1024$ corresponds to a 95% Wilson confidence lower bound of $91.2\%$. Perfect eavesdropper detection is mathematically impossible for finite sample sizes.
